# rxjava-study

## Documentation Format

All notes are written in **Asciidoctor** (`.adoc` files), not Markdown. Asciidoctor is far more expressive and powerful. JetBrains editor plugins support the format.

## Directory Structure

```
[topic]-study/
├── README.adoc
├── inbox/
├── notes/
├── projects/
└── references/
```

### Subdirectory Purposes

| Directory | Content |
|-----------|---------|
| **notes/** | Concepts, explanations, patterns, interpretations (e.g., `buffers.adoc`) |
| **projects/** | Code experiments, organized by language or concept |
| **references/** | Curated links, talk summaries, book notes, external snippets |
| **inbox/** | Rough ideas and incomplete thoughts; a brain dump |

## Key Practices

- **File naming**: Use descriptive names reflecting the content (e.g., `topic-summary.adoc`)
- **Cross-referencing**: Add related notes and prerequisites at the top of each section
- **Version control**: All notes are committed to this private repository
- **Accessibility**: Keep this study project readily accessible for quick reference updates
- **Content separation**: Private notes live here; public derivative work (presentations, workshops, articles) goes in separate repositories

## Knowledge Management Philosophy

"Keep Notes Private, Make Knowledge Public" — transform private learning into public deliverables through presentations, articles, and workshops.
